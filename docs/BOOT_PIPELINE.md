# Screaming Penguin Boot Pipeline (v0)

This document describes the current Screaming Penguin ISO boot path and the planned migration to a custom installer initramfs.

## 1. Current Behaviour (Broken)

As of Phase 10.5, the ISO boots via GRUB but drops into an initramfs shell with:

> No root device specified. Boot arguments must include a root= parameter.

The current pipeline is:

1. `tools/make_installer_iso.sh` builds an ISO tree using:
   - A Linux kernel image (vmlinuz) copied from the Debian build.
   - A stock Debian `initrd.img` (generated by the base system), not a Screaming Penguin–specific installer initramfs.
2. GRUB is configured to:
   - Load `/boot/vmlinuz` as the kernel.
   - Load `/boot/initrd.img` (or equivalent) as the initrd.
   - Pass limited or no `root=` / `rdinit=` arguments.
3. At boot, the kernel unpacks the Debian initramfs, which expects a real root filesystem device and a matching `root=` parameter.
4. Because the installer ISO does not provide a traditional root filesystem and the kernel command line does not include a valid `root=` device, the initramfs cannot mount any root and drops to an emergency shell.

The Screaming Penguin installer logic (CONFIG partition scan, YAML parsing, rootfs extraction, etc.) never runs in this path.

## 2. Target Behaviour (Planned)

The planned design for the boot path is:

1. Build a **custom installer initramfs** that:
   - Contains a very small root filesystem (BusyBox + required tools).
   - Uses `/init` as the entrypoint.
   - Mounts `/proc`, `/sys`, and `/dev`.
   - Locates the CONFIG partition by label (`CONFIG`).
   - Mounts `/mnt/config` and reads:
     - `config/installer-config.yml`
     - `config/<rootfs>.tar.gz`
   - Partitions and formats the target disk.
   - Extracts the Debian rootfs tarball.
   - Configures hostname, user, locale, timezone, SSH, and bootloader.
   - Installs GRUB onto the target disk and reboots.

2. Update the ISO builder to:
   - Use the Screaming Penguin **installer initramfs** instead of Debian’s stock `initrd.img`.
   - Place it at a known path in the ISO tree (for example, `/boot/initrd-installer.img`).

3. Update GRUB configuration to:
   - Present a single menu entry: **Screaming Penguin Installer**.
   - Load `/boot/vmlinuz` as the kernel.
   - Load `/boot/initrd-installer.img` as the initrd.
   - Pass explicit boot arguments, for example:
     - `root=/dev/ram0` to indicate the root filesystem comes from the initrd.
     - `rdinit=/init` to execute the installer `/init` script.
     - Optional: `quiet` or other cosmetic flags.

This design makes the installer fully responsible for locating the CONFIG partition and preparing the target disk. Debian’s stock initramfs is not used.

## 3. High-Level Implementation Plan

The implementation will be done in follow-up checkpoints:

1. **Installer Initramfs Builder**
   - New script: `tools/build_installer_initramfs.sh`.
   - Stages a small root filesystem (BusyBox + required utilities).
   - Copies the Screaming Penguin installer `/init` and support scripts.
   - Produces `build/runtime-installer/initrd.img-installer`.

2. **ISO Builder Integration**
   - Update `tools/make_installer_iso.sh` to:
     - Invoke `tools/build_installer_initramfs.sh`.
     - Copy the new `initrd.img-installer` into the ISO tree.
     - Ensure kernel and initrd paths are consistent with GRUB.

3. **GRUB Configuration**
   - Replace the existing stock GRUB config with a Screaming Penguin–specific template that:
     - Uses `root=/dev/ram0 rdinit=/init`.
     - Does not reference Debian root devices.
     - Boots directly into the installer.

4. **Installer `/init` Responsibilities**
   - Mount /proc, /sys, /dev.
   - Locate CONFIG by label.
   - Mount CONFIG to `/mnt/config`.
   - Read `installer-config.yml` and rootfs tarball.
   - Partition and format target disk.
   - Extract rootfs and configure system.
   - Install GRUB to target disk.
   - Reboot on success, or drop to a diagnostics shell on failure.

5. **CI & Smoke Tests**
   - Add CI checks to confirm:
     - The custom installer initramfs contains an `/init` script.
     - The ISO contains the installer initrd at the expected location.
     - The GRUB config uses the installer initrd and the correct kernel arguments.

This checkpoint (P10.5·A) does not implement the above behaviour; it only documents the design and records the current broken state.

## 4. Constraints and Non-Goals

- No behaviour changes in this checkpoint; the ISO boot behaviour remains broken.
- No changes to QEMU CI smoke tests yet.
- No attempt to make the Debian stock initramfs work; the installer initramfs will be the single source of truth.
- v1 scope remains x86_64, full-disk wipe, GPT + EFI + ext4 rootfs.
