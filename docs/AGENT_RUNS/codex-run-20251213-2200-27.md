Added a dedicated rescue helper so an actual shell is always available when config discovery fails, and wired it into init/config discovery plus the unit tests.

- **Rescue helper** `installer/runtime/lib/rescue_mode.sh:1` now logs a clear header, runs `lsblk -f`/`blkid`/`SP_RESCUE_LABEL_DIR` diagnostics, records write-gate blocking, hunts down a shell (including `SP_TEST_RESCUE_SHELL` overrides), execs it onto the console, and falls back to an endless sleep if no shell is found; SC2093/SC2094 are intentionally suppressed on the `exec` line because the process must never return.
- **Boot wiring** `installer/init/init.sh:31` now sources the helper before any other runtime library, and `installer/runtime/lib/config_discovery.sh:17` sources it for standalone runs before calling `sp_enter_rescue_mode("missing-config")` whenever discovery exhausts its attempts.
- **Deterministic tests** `tests/installer/test_config_discovery.py:109` exercises the new rescue path (logs contain “Entering rescue mode” plus `source=lsblk`/`blkid`/`by-label`, and the stub shell is exec’d), backed by `tests/installer/bin/rescue-shell:1` which records invocation details and exits with a configurable status.
