Trimmed the ISO paths so PR CI and helper tooling now only build/validate the canonical `.img`, while all ISO helpers either fail fast or live only in the archival analysis notes.

- `Makefile` no longer drives `make iso`, `ci-iso`, or release packaging with an ISO; those targets now print a deprecation message and abort, the `dist-release` workflow only copies `dist/screaming-penguin.img`, and the QEMU acceptance workflow (`.github/workflows/qemu-acceptance-ci.yml`) now runs `make img` before the harness. The ISO workflow (`.github/workflows/ci-iso-build.yml`) and the legacy `ci/qemu_smoke_ci.sh` script were removed, and the ISO build helpers in `tools/` now terminate with a “use the Ouroboros side project” message.
- Documentation now emphasises `.img` as the sole supported artifact: `README.md`, `docs/CI.md`, `docs/CI_OVERVIEW.md`, `docs/GETTING_STARTED.md`, `docs/INSTALLER_USAGE.md`, `docs/QEMU_TESTS.md`, `docs/BOOOT_PIPELINE.md`, `docs/ISO_BUILD.md`, and the archival `docs/USING_ISO.md` all either remove ISO instructions or flag them as historical, and the new analysis note in `docs/analysis/sp-mp-prune-iso-analysis.md` captures the motivation and plan for the `<img>`-only strategy.
- Test harnesses and suites were updated to drop ISO coverage: `tests/harness/qemu-*` now tell users to run `make img`, `tests/installer/test_installer_media_bootability.py` focuses solely on the `.img` layout while the ISO-only `test_installer_iso_initramfs.py` was deleted, and the tests now verify each partition/ESP/kernel file without ever referencing an ISO.
- ISO helper scripts (`tools/make_installer_iso.sh`, `tools/ci_iso.sh`) were rewritten as fail-fast stubs so any accidental invocation gives a clear “ISO builds are disabled here” message; this satisfies the “fail fast” requirement while keeping the historical files for reference.
