**Changes**
- Added a tiny helper and guard around the shell loop so rescue mode now logs `[SP-INSTALLER][WARN] rescue noninteractive; skipping shell` and returns 1 whenever stdin isn’t a TTY or `SP_RESCUE_NONINTERACTIVE=1`, while `SP_RESCUE_FORCE_INTERACTIVE=1` overrides that guard so interactive tests and real consoles still drop into the shell (`installer/runtime/lib/rescue_mode.sh:21-235`).
- Config discovery now honors a toggle (`SP_CONFIG_REQUIRE_BY_LABEL`, default `0`) before forcing rescue when the by-label namespace is missing/empty, and it emits a `[SP-INSTALLER][WARN] … continuing fallback discovery` log instead of aborting for the permissive case (`installer/runtime/lib/config_discovery.sh:32-144`, `:668-683`).
- Tests were updated to match the new runtime behavior: `_run_command` in `tests/installer/test_bootstrap_dev_nodes.py` now defaults `SP_RESCUE_NONINTERACTIVE=1` so bootstrap tests never hang on a console; `test_missing_config_triggers_rescue` and `test_rescue_shell_restarts` explicitly set `SP_RESCUE_FORCE_INTERACTIVE=1` so they still exercise the stubbed shell (`tests/installer/test_bootstrap_dev_nodes.py:20-49`, `tests/installer/test_config_discovery_busybox.py:336-352`, `tests/installer/test_rescue_mode.py:38-79`); `test_rescue_on_empty_by_label_namespace` now requires the strict-by-label toggle, skips the shell via `SP_RESCUE_NONINTERACTIVE=1`, captures the fatal marker via `SP_LOG_DEVICE`, and verifies the diagnostic dumps instead of the shell log (`tests/installer/test_config_discovery_busybox.py:372-388`); and the util-linux whitelist test now ignores `rescue_mode.sh` when checking for `blkid`/`lsblk` references since rescue mode intentionally runs those probes (`tests/installer/test_config_discovery_busybox.py:424-435`).
