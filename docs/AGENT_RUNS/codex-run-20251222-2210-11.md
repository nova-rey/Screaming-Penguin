**Config Fallback**
- Introduced `SP_CONFIG_FS_TYPES` parsing and ordered fallback attempts so `sp_mount_candidate` iterates over the configured list, runs `sp_try_load_fat_modules` before the first `vfat`, logs `[SP-INSTALLER] config-mount-ok …` on success, and emits a single `[SP-INSTALLER][FATAL] config-mount-failed …` if every filesystem fails (`installer/runtime/lib/config_discovery.sh:40-90` and `:333-370`).
- Rescue mode now always emits `/proc/filesystems`, `lsmod`, and a `modprobe vfat` rc when `SP_CONFIG` mounts failed for a `vfat` attempt, making diagnostic dumps more helpful when the kernel lacks the VFAT driver (`installer/runtime/lib/rescue_mode.sh:160-193`).

**Docs & Tests**
- Documented the new `SP_CONFIG_FS_TYPES` knob, defaulting to `vfat` with optional `ext4` fallback, and noted the helpful vetting in both the config-discovery guide and the MP analysis write-up (`docs/CONFIG_DISCOVERY.md:3-12`, `docs/analysis/mp-config-fs-fallback.md:1-33`).
- Added a regression test that simulates a `vfat` failure and verifies the ext4 fallback logs and success path, backed by an enhanced `tests/installer/bin/mount` stub that can selectively fail specific filesystems (`tests/installer/test_config_discovery_busybox.py:185-206`, `tests/installer/bin/mount:1-73`).
