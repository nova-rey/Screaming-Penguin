# MP Fix SP_CONFIG label probe

## Discovery engine
- The canonical SP_CONFIG hunter lives in `installer/runtime/lib/config_discovery.sh`; the initramfs copy under `build/installer-initramfs/runtime/lib/config_discovery.sh` is supposed to stay byte‑for‑byte in sync so the in‑ramfs bootstrap runs the same helper as the installed runtime.
- Label probing is centered on `sp_try_label_candidate` → `sp_find_partition_by_fs_label`, and those helpers still require `blkid -o export` while an explicit `SP_CONFIG_LABEL` (or custom `SP_CONFIG_LABEL_NAME`) causes the script to hard‑fail if the label cannot be resolved (`sp_log_fatal_marker` + the final `config-label-not-found` fatal in `sp_discover_config`).

## Initramfs failure surface
- The installer initramfs tree under `build/installer-initramfs` contains only `bin`, `init`, `lib/modules`, and `runtime`; there is no `/dev` at build time (`/dev` gets populated by `mdev`). When `sp_enter_rescue_mode` runs it logs `source=by-label note=missing path=/dev/disk/by-label` from `installer/runtime/lib/rescue_mode.sh`, which proves the `/dev/disk/by-label` path is absent inside initramfs. Discovery therefore cannot rely on those symlinks.
- `sp_find_partition_by_fs_label` begins with `command -v blkid` and immediately emits `[SP-INSTALLER][FATAL] blkid-not-found` if the binary is missing. The initramfs currently only stages `busybox` and a handful of symlinks under `build/installer-initramfs/bin`, and the linked `blkid` binary (if it exists at all) is a dynamically linked util-linux ELF that needs `/lib64/ld-linux-x86-64.so.2` and friends, but the initramfs does not include `/lib64`. As a result, `blkid` is effectively absent inside the BusyBox initramfs, so the label probe can't even start and the bootstrap drops into rescue while still logging `source=by-label` diagnostics.
- Because label probing short‑circuits before any devices are mounted, the fatal path for `SP_CONFIG_LABEL_REQUESTED` is always triggered, and rescue mode takes over even though the real disk and label might be present once the target environment boots.

## Initramfs staging pipeline
- `tools/build_installer_initramfs.sh` builds the staging tree rooted at `build/installer-initramfs`. It links BusyBox applets (`sh`, `mount`, `mkdir`, etc.) into `build/installer-initramfs/bin/`, copies `runtime/lib` helpers (`config_discovery.sh` included) from `installer/runtime/lib`, and installs `/init` from the source tree. The same script also enforces the minimum initramfs size and checks that `init` exists, so it is the natural place to stage `blkid` (and any supporting libs) if a real label resolver is to live inside the initramfs.
- The discovery helpers expect to run out of `${SP_DEV_ROOT:-/dev}` and `${SP_PROC_PARTITIONS:-/proc/partitions}` in initramfs; those paths are set from `init` before sourcing `config_discovery.sh`. Any helper binary we add for label probing therefore needs to be placed under `build/installer-initramfs/bin/` so it ends up in the initramfs image and is found on the default `/bin:/sbin:/usr/bin:/usr/sbin` PATH that `init` supplies.

These observations explain why SP_CONFIG label discovery currently fails hard when initramfs boots without udev: `/dev/disk/by-label` isn’t there, `blkid` (and its libs) aren’t present, and the existing helpers still assume both resources exist before they try to mount anything.
