# Phase 12 Checkpoint 1 — Bootloader Analysis

## A1. Repository survey
- `installer/init/init.sh` already handles SP mode detection, the `installer.write_gate` discipline, disk probing, and the planner/executor pipeline via `installer/runtime/lib/disk_layout.sh` and `installer/runtime/lib/disk_execute.sh`, but it currently stops after disk execution and does not invoke rootfs extraction, chroot work, or any bootloader-specific logic.
- The runtime tree already provides reusable helpers and scripts (`installer/runtime/lib/logging.sh`, `config_validation.sh`, `safety_checks.sh`, `sp-rootfs-apply.sh`, `sp-chroot-setup.sh`) that cover config parsing, safety gating, and hosting chroot steps (hostname, timezone, user, SSH, GRUB) when run under the Phase 5 orchestrator, although the init path never calls them.
- Tests under `tests/installer` cover the planner, executor, and init write-gate enforcement, but there is no harness that exercises bootloader or fstab generation logic yet. The docs (`docs/CONFIG_SCHEMA.md`, `docs/installer_contract.md`, `docs/architecture.md`, the existing Phase 9/10 roadmaps, and `docs/DEV_ROADMAP.md`) describe planner/executor gating but not a dedicated bootloader phase.

## A2. Bootloader stage requirements
1. Phase 12 must mount the EFI partition, extract the rootfs, and install GRUB inside the chroot only after the disk executor has successfully run, respecting `installer.write_gate`, `SP_ENABLE_DISK_EXECUTE=1`, and the new `SP_ENABLE_BOOTLOADER=1` toggle, plus skip/debug knobs (`SP_SKIP_BOOTLOADER`, `SP_DEBUG_BOOTLOADER`).
2. The stage must emit `[SP-INSTALLER] bootloader START/END` markers, regenerate `/etc/fstab` using `blkid` UUIDs for the boot/root partitions, chroot to run `grub-install --target=<configured target> --efi-directory=/boot/efi --bootloader-id=<name>` and `grub-mkconfig`/`update-grub`, and produce a minimal but valid `grub.cfg` even if kernel names are generic.
3. Bootloader config needs to live under `installer.bootloader` in `installer-config.yml` with defaults such as `grub_efi_target: x86_64-efi`, `grub_bootloader_id: ScreamingPenguin`, timeout and fstab opt overrides; these values must also be validated in `installer/runtime/lib/config_validation.sh` so future runtime consumers share the same schema.
4. Documentation must capture the new phase (new `docs/Phase12_Roadmap.md`, updates to `docs/architecture.md`, `docs/installer_contract.md`, `docs/CONFIG_SCHEMA.md`, and `docs/DEV_ROADMAP.md`), describe the new skip/debug flags, and explain the final install order (planner → executor → rootfs deploy → bootloader → complete).
5. Tests must cover fstab writing, the chroot command assembly, the gating and skip/debug behaviors, and ensure the init script reaches the bootloader stage only when the correct toggles are present (`tests/installer/test_bootloader.py`).

## A3. Implementation plan for Block B (Phase 12)
- Create `installer/runtime/lib/bootloader.sh` with helpers to mount EFI, generate `/etc/fstab` from `blkid` UUIDs, build `grub.cfg`, run the chrooted `grub-install`/`update-grub` commands, and a wrapper `sp_install_bootloader_and_finalize` that logs START/END plus respects `SP_ENABLE_BOOTLOADER`, `SP_SKIP_BOOTLOADER`, and `SP_DEBUG_BOOTLOADER`, while re-enforcing the write gate.
- Wire the stage into `installer/init/init.sh`: source the new bootloader helper, a resilient copy of `sp-rootfs-apply.sh`, and the safety library; parse `rootfs.path` (falling back to `/config/rootfs/debian-rootfs.tar.gz`), run the rootfs extraction right after the executor when `SP_ENABLE_DISK_EXECUTE=1`, then call `sp_install_bootloader_and_finalize`, finally writing `[SP-INSTALLER] COMPLETE` to close the run.
- Extend `installer/runtime/lib/config_validation.sh` to read the `installer.bootloader` section values (defaulting to the chosen target, timeout, FSTAB options, and bootloader ID) and export them for reuse by runtime components.
- Update schema/config docs with the new `installer.bootloader` block and mention the skip/debug flags as part of the Phase 12 roadmap entries, and adjust `docs/DEV_ROADMAP.md` to describe Phase 12 progress.
- Build `tests/installer/test_bootloader.py` to run the new helpers under controlled environments, stubbing `blkid`/`chroot` where necessary, checking that `/etc/fstab` gets rewritten with UUIDs, ensuring commands are assembled, and validating gating (SKIP vs ENABLE toggles) so the main init path only enters the bootloader stage when allowed.

With this understanding, proceed straight into Block B implementation without pausing.
