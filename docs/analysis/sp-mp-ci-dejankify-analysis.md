# SP-MP CI Dejankify – Analysis

## CI Surface Scan
- `.github/workflows/ci.yml` is the only workflow that fires for `pull_request` events. The `jobs.ci` job (Lint, Build Image, QEMU Smoke) installs deps, runs `shellcheck`, builds the ISO via `make iso`, and finally launches `ci/qemu_smoke_ci.sh`. The nearly two-hour ISO build plus a QEMU smoke pass is what currently runs until GitHub Actions kills the run after ~24h with no further logs.
- Other workflows (`installer-runtime-ci.yml`, `qemu-acceptance-ci.yml`, `rootfs-ci.yml`, `dist-release-ci.yml`) either run on weekly schedules or require manual triggers; they already have their own runtimes and do not gate PR validation.
- The `Makefile` targets invoked by CI are `make iso` (PR workflow) and `make rootfs`/`make qemu-acceptance` (scheduled workflows); `make iso` dereferences `$(RUNTIME_DIR)/.installer-runtime-built`, so both `tools/build_runtime.sh` and `tools/build_installer_initramfs.sh` run under its hood before `tools/make_installer_iso.sh`.
- CI shells rely on `tools/*.sh` scripts (`build_runtime.sh`, `build_installer_initramfs.sh`, `make_installer_iso.sh`, and `ci/qemu_smoke_ci.sh`) along with `tests/harness/qemu-smoke-test.sh` and `tests/harness/qemu-acceptance.sh`, though only the former is exercised on PRs.
- Tests that can hang include those that spawn QEMU (`tests/harness/qemu-smoke-test.sh`), debootstrap-based installers (`tools/build_runtime.sh`), and ISO builders that wait on `grub-mkstandalone`/`xorriso` (`tools/make_installer_iso.sh`).

## Current PR Hang Surface
- The `jobs.ci` job within `.github/workflows/ci.yml` is tied directly to `pull_request` events. It never sets a job-level `timeout-minutes`, so the default GitHub limit (~24h) is reached after `make iso` stalls on networking or the installer initramfs/ISO phases. Because the ISO build precedes every smoke test, the job spends hours in `build_runtime.sh`/`make_installer_iso.sh` before even touching the QEMU harness, leaving no fast feedback for PR authors.

## Top Hang Risk Points
1. `tools/build_runtime.sh` – Runs `debootstrap` (minbase variant) against `deb.debian.org` and installs `linux-image-amd64` inside a chroot (`Makefile` target `$(RUNTIME_DIR)/.installer-runtime-built` invoked by `make iso`). Without timeouts or heartbeat messages, this can spin waiting for apt locks, TTY prompts, or unreachable mirrors, and it’s a known blocking point when `/dev/null` is missing.
2. `tools/make_installer_iso.sh` – Drives GRUB tooling (`grub-mkstandalone`, `xorriso`, `grubx64.efi`) and copies kernel/initrd artifacts. Long disk/image writes and network-aware bootstrap steps can hang silently under `timeout` defaults; the current PR job doesn’t bound it nor emit progress markers between “runtime build”, “installer initramfs”, and “ISO assembly”.
3. `tests/harness/qemu-smoke-test.sh` – Called from `ci/qemu_smoke_ci.sh` (PR job) and simply runs `qemu-system-x86_64` with no wrapper or timeout. When the guest never boots or waits for input, the job shows no output for hours. The script should either limit runtime or at least echo a heartbeat while the VM is running.

## Recommended Changes
- Replace `.github/workflows/ci.yml` with a dedicated **CI Smoke** workflow that runs on `pull_request`, installs `shellcheck`, runs `shellcheck tools/*.sh`, executes `python3 -m compileall -q .`, and exercises the targeted installer unit tests (e.g., `pytest tests/installer`). Add optional `ruff`/`black` guards only when configs exist (`pyproject.toml`, `.ruff.toml`, `setup.cfg`, etc.), and wrap all steps with `bash -euo pipefail`. Add `timeout-minutes: 30` to keep PR CI bounded.
- Create a new workflow for the full ISO build (manual `workflow_dispatch` + nightly `schedule`). Use the new `make ci-iso` target to run `make installer-runtime` and `make iso`, insert logging breadcrumbs before/after the runtime, initramfs, and ISO stages, and wrap each stage with the heartbeat/timeout helper (e.g., `timeout 60m bash tools/ci_heartbeat.sh --label "Runtime" make installer-runtime`). Set job-level `timeout-minutes` (90–180) and upload `build/`, `dist/`, and a `ci-debug-summary.txt` artifact when failures occur.
- Add a lightweight heartbeat wrapper (`tools/ci_heartbeat.sh`) so any long-running shell steps can echo progress, and invoke it from ISO-leading commands and the QEMU smoke test.
- Add `make ci-smoke` and `make ci-iso` targets that call the scripted smoke commands and ISO build, respectively, so the workflows can refer to them without duplicating command sequences.
- Document the two CI surfaces and local run instructions in `docs/CI.md`, plus capture this analysis summary in `docs/analysis/sp-mp-ci-dejankify-analysis.md` so future agents understand why PR CI became smoke-only and how the nightly ISO runs behave.
